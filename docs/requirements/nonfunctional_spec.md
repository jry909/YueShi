# 软件系统非功能需求规范

> 项目：教学能力评估智能体（约师）
> 版本：v1.0 ｜ 文档类型：需求阶段 — 非功能需求规范
> 配套文档：[functional_spec.md](functional_spec.md) · [problem_definition.md](problem_definition.md)

---

## 0. 范围说明

本规范仅覆盖**教学能力评估智能体**。以下内容**不在范围内**：

- 学科知识准入测试（不做、不设计、不依赖）
- 家教平台的订单、支付、IM、搜索推荐等业务功能
- 其他学段与学科
- 实时语音交互与视频多模态分析

> 非功能需求必须**可度量、可验证**。本文每条需求均给出目标值与验证方式。

## 2. 性能需求 (NFR-P)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-P1 | 媒体上传速度 | 10 分钟录音（≤15 MB）在 4G 网络下 **≤ 60 秒**完成 | 真机 4G 实测 |
| NFR-P2 | 语音转写时长 | 全部轮次音频合计 ≤ 20 分钟时，转写 **≤ 4 分钟**完成（P95） | 批量压测统计 |
| NFR-P3 | AI 评分时长 | 单会话全部维度评分 **≤ 7 分钟**（P95，含多轮转写） | 批量压测统计 |
| NFR-P4 | 端到端出分 | 最后一轮提交至 AI 初评可见 **≤ 15 分钟**（P95） | 全链路埋点 |
| NFR-P5 | 报告页加载 | 首屏 **≤ 3 秒**（P95） | 前端性能监控 |
| NFR-P6 | 并发能力 | 支持 **≥ 50** 个会话并行处理不排队 | 压测 |
| NFR-P7 | 复核工作台响应 | 打开对照视图 **≤ 3 秒** | 性能测试 |

> **多轮假设**：本表按「平均 2 条疑问（讲题 1 段 + 回应 2 段，合计音频 ≈ 17 分钟）、上限 3 条疑问（≈ 21 分钟）」测算；答辩轮数由题目「疑问队列」长度决定。

## 3. 可靠性与可用性 (NFR-R)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-R1 | 录制不丢失 | 断网 / 切后台 / 崩溃后，**已录音频不丢失**，可恢复续录 | 故障注入测试 |
| NFR-R2 | 异步任务可靠性 | 转写与评分任务**至少执行一次**，失败自动重试 ≤ 3 次 | 任务日志核查 |
| NFR-R3 | 评分服务降级 | 评分服务不可用时降级为「待人工评分」，**不阻塞试讲者** | 故障演练 |
| NFR-R4 | 系统可用性 | 月度可用性 **≥ 99.5%** | 监控统计 |
| NFR-R5 | 数据持久性 | 媒体与评分数据年丢失率 **< 0.01%** | 存储冗余核查 |
| NFR-R6 | 幂等性 | 重复提交同一会话不产生重复评分或重复发证 | 接口测试 |

## 4. 安全与隐私 (NFR-S)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-S1 | 传输加密 | 全链路 **TLS 1.2+** | 安全扫描 |
| NFR-S2 | 存储加密 | 音视频与个人信息静态加密 **AES-256** | 配置核查 |
| NFR-S3 | 访问控制 | 试讲者**仅可访问本人**材料；复核员按需授权、最小权限 | 越权测试 |
| NFR-S4 | 媒体防扩散 | 试讲音视频下载需授权，可加水印 | 功能验证 |
| NFR-S5 | 数据删除权 | 用户注销后 **30 天内**删除音视频与个人信息 | 流程审计 |
| NFR-S6 | 审计日志 | 全链路关键操作留痕，**留存 ≥ 6 个月** | 日志核查 |
| NFR-S7 | 敏感信息最小化 | 转写文本入库前脱敏（手机号、住址等） | 抽样核查 |

## 5. 合规需求 (NFR-C)

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-C1 | 生成式 AI 服务备案 | 若 AI 评分对外提供服务，需完成相关备案 |
| NFR-C2 | 个人信息保护 | 遵循告知同意、最小必要原则，提供查阅 / 更正 / 删除通道 |
| NFR-C3 | 肖像与录音授权 | 试讲开始前须取得试讲者的肖像与录音使用授权 |
| NFR-C4 | AI 评分透明性 | 评分结果必须可解释（附理由），并提供申诉渠道 |
| NFR-C5 | 数据出境 | 若使用境外模型 / 服务，须评估数据出境合规性 |

## 6. 评分质量需求 (NFR-Q) —— 核心

> 本节是本项目**最重要的非功能需求**。评分质量不达标，整个系统不成立。

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| **NFR-Q1** | **AI 与人工评分一致性** | Kappa / ICC **≥ 0.75** | 双评分者一致性统计 |
| NFR-Q2 | 评分可解释性 | **每个维度得分必须附带文字理由**，禁止无理由分数 | 结果结构校验 |
| NFR-Q3 | 评分可复现性 | 同一输入 + 同一 rubric 版本 + 同一模型版本，档位偏差 **≤ 1 档** | 重复评分实验 |
| NFR-Q4 | 版本可追溯 | 每条评分记录可追溯至具体 **rubric 版本 + 提示词版本 + 模型版本** | 数据核查 |
| NFR-Q5 | 一票否决可靠性 | 学科准确性触发否决时，结论 **100%** 判为未过，不可被权重覆盖 | 单元测试 + 抽样 |
| NFR-Q6 | 理由无幻觉 | 评分理由**不得引入转写文本中不存在的内容**，抽检不合规率 **< 2%** | 人工抽检 |
| NFR-Q7 | 人工复核覆盖 | 上线初期 **100% 复核**；稳定后按抽检策略，覆盖率 **≥ 20%** | 流程统计 |
| NFR-Q8 | 区分度 | 各维度评分分布标准差 **> 0.8**，避免全给中间分 | 分布统计 |
| NFR-Q9 | 内部一致性 | 维度间 Cronbach's α **≥ 0.7** | 统计分析 |
| NFR-Q10 | 重测稳定性 | 同一人两次试讲总分差异 **≤ 10 分** | 重测实验 |

## 7. 可维护性与可扩展性 (NFR-M)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-M1 | Rubric 可配置 | 调整维度 / 分档描述 / 权重 / 阈值**无需改代码** | 配置化验证 |

| NFR-M3 | 提示词版本化 | 评分提示词纳入版本管理，支持灰度与回滚 | 版本系统核查 |
| NFR-M4 | 线性扩展 | 增加评估量时可通过扩容 worker 线性提升吞吐 | 压测 |
| NFR-M5 | 学科扩展预留 | 数据结构预留多学科字段（**本期不实现新学科**） | 模型评审 |

## 9. 成本需求 (NFR-$)

| 编号 | 需求 | 目标值 |
|---|---|---|
| NFR-$1 | 单次评估 AI 成本 | ASR + LLM 调用合计 **≤ 1 元 / 次** |
| NFR-$2 | 算力门槛 | 第一版**全 CPU 可跑通**，不强制要求 GPU |
| NFR-$3 | 存储成本 | 音频按需转档，长期存储可用低成本存储层 |

> **多轮成本测算**（平均 2 条疑问 = 3 段音频，≈ 17 分钟）：转写文本约 3000 字（≈2500 tokens），LLM 输入约 4500 tokens（含 rubric 提示）、输出约 750 tokens。按中档 API 计：LLM ≈ ¥0.07 / 次，ASR 自托管摊薄 ≈ ¥0.02（走 API 约 ¥0.2~0.4）。**合计 ≈ ¥0.1~0.5，仍落在 ≤ 1 元预算内**，约为双轮的 1.3 倍，无需放宽 NFR-$1。

## 12. 需求优先级与验收

| 优先级 | 编号 | 说明 |
|---|---|---|
| **P0 必须达标** | NFR-Q1 ~ Q5、NFR-R1、NFR-R3、NFR-S1 ~ S3、NFR-C2 ~ C4、NFR-P2 ~ P4 | 不达标则系统不成立 |
| **P1 重要** | NFR-P1、P5 ~ P7、NFR-R2、R4 ~ R6、NFR-S4 ~ S7、NFR-Q6 ~ Q10、NFR-M1 ~ M3、NFR-O1 ~ O4、NFR-$1 ~ $2、NFR-X1 ~ X4、NFR-U1 ~ U4 | 第一版应有 |
| **P2 可延后** | NFR-C1、NFR-C5、NFR-M4 ~ M5、NFR-$3 | 视上线节奏安排 |

### 验收门槛（一句话）

> **NFR-Q1（AI 与人工评分一致性 Kappa / ICC ≥ 0.75）是整个系统的验收红线**，其余需求围绕它服务。
